Context & Objectives

Problem Statement & Biometric Motivation

The Security Dilemma

Static passwords (what you know) are vulnerable to observation, credential theft, and brute-force dictionary attacks. Physical biometrics (fingerprints/iris) require costly, dedicated hardware.

The Behavioral Solution

Keystroke dynamics verifies how a user types rather than just what they type. It requires zero additional hardware, operating on standard keyboards.

Core Machine Learning Challenge

Authenticate enrolled user s002 (Class 1) against 50 zero-effort impostors (Class 0) under extreme 1:50 class imbalance (~1.96% genuine, 98.04% impostor) across multi-day temporal sessions.

Speaker Notes: "Here I explain the motivation: passwords can be stolen or observed, but keystroke dynamics requires zero extra hardware—it uses regular keyboards. In our 1-vs-all setup with user s002, the biggest hurdle is the severe 1:50 class imbalance, where genuine logins make up less than 2% of the test data."
Biometric Modality

Keystroke Mechanics & The 31 Features

Extracted from 400 repetitions of password .tie5Roanl across 3 timing dimensions:

1. Hold Times (H)

11 features ($t_{\text{rel}} - t_{\text{press}}$). Key dwell duration. Top discriminative feature: H.Shift.r (ANOVA $F > 280$).

2. Keydown-Keydown (DD)

10 digraph latencies ($t_{\text{press}, 2} - t_{\text{press}, 1}$). Captures finger flight speeds between successive keys.

3. Keyup-Keydown (UD)

10 inter-key intervals ($t_{\text{press}, 2} - t_{\text{rel}, 1}$). Preserves negative values (Key Rollover).

Physical Justification: Key Rollover ($UD < 0$)

In fluent typing, the typist strikes key $k+1$ before releasing key $k$. Exactly 22,118 samples (10.84% of all UD values) are negative in our dataset. Our Pydantic contract strictly accepts negative values as authentic biometrics.

Speaker Notes: "Walk through the 31 features: 11 hold times, 10 DD flight times, and 10 UD intervals. A key technical finding here is that 10.84% of all UD values are negative because fast typists overlap keys (key rollover). Instead of treating this as bad data, our system preserves it as an authentic biometric feature."
Data Exploration

Exploratory Data Analysis Highlights

CMU Benchmark Dataset Profile

  • 20,400 rows, 34 columns (31 timing features).
  • 51 subjects, 400 reps each across 8 sessions.
  • Zero missing values and zero duplicates.
  • Positive skewness in flight times due to pauses.

Statistical Insights

  • ANOVA F-Test: H.Shift.r, H.t, H.i exhibit highest between-subject vs within-subject variance.
  • Collinearity: Digraph identity $DD \approx H + UD$ causes multicollinearity ($r > 0.85$).
  • Session Drift: Mean hold times decrease from Session 1 to 4 as users adapt to the password.
Speaker Notes: "Highlight the dataset quality: 20,400 rows with zero missing values. Point out our ANOVA F-test findings where H.Shift.r showed the highest between-subject variance (F > 280), making it the single most discriminative feature for identifying user s002."
Methodology

Leakage-Free Preprocessing & The 1:50 Imbalance Trap

Temporal Partitioning (No Leakage)

Random row splits leak intra-day typing fatigue. We strictly enforce:

  • Train: Sessions 1–3 ($N = 7,650$)
  • Validation: Session 4 ($N = 2,550$) — EER tuning
  • Holdout Test: Sessions 5–8 ($N = 10,200$)

Dimensionality Reduction (PCA)

StandardScaler fit on Train only.
PCA(n_components=0.95) reduces 31 collinear features to 17 orthogonal components while retaining 95.2% variance.

The 99% FRR Baseline Trap (Why Accuracy is Deceptive)

Under 1:50 class imbalance, a default classifier achieves 97.90% accuracy simply by predicting "Impostor" for 100% of logins. Out of 200 genuine test attempts, it rejected 199 ($\text{FRR} = 99.50\%$). Balanced weighting and threshold tuning are mandatory.

Speaker Notes: "Explain the accuracy paradox: our midterm model had 97.9% accuracy but rejected 99.5% of genuine user logins because it just predicted 'impostor' every time. We fixed this by balancing class weights and tuning the decision threshold on Session 4 validation data to the Equal Error Rate point."

Experiment Tracking & Model Selection

Model Comparison: Why Random Forest in Production?

Unseen Holdout Test on Sessions 5–8 ($N = 10,200$: 200 Genuine, 10,000 Impostor) across 3 distinct algorithm families:

Model Configuration Algorithm Family Threshold (τ) FAR FRR ROC-AUC EER
01 Baseline Logistic Regression Linear Model 0.5000 0.15% 99.50% 0.9017 17.00%
02 Balanced Logistic Regression Linear Model 0.4445 9.91% 25.00% 0.9161 14.44%
03 Random Forest (Production) Tree Ensemble 0.1094 12.05% 54.50% 0.8582 20.03%
04 Support Vector Machine (RBF) Kernel Method 0.0071 4.88% 33.00% 0.8223 22.91%

Performance vs. Explainability Trade-Off

Metric Leaders: Balanced Logistic Regression achieved best EER (14.44%) & ROC-AUC (0.9161); SVM achieved lowest FAR (4.88%).

Why RF Was Retained: Random Forest natively yields Mean Decrease in Impurity feature importances (classifier.feature_importances_), powering our UI's real-time keystroke mismatch diagnostics with zero latency overhead.

Holdout Integrity & Option B Calibration

Holdout Integrity: Sessions 5–8 were never used for calibration or tuning. RF was chosen a priori as the serving template, not retroactively switched post-hoc.

Option B Calibration: Strictly paired pipeline fitted on Sessions 1–3 ($N=7,650$) and calibrated on Session 4 (τ = 0.1094). Avoided refitting on S1–4 to prevent distribution shift.

Speaker Notes: "Walk the panel through our 4-model comparison across 3 algorithm families. Be completely transparent: Balanced Logistic Regression achieved our best EER of 14.44% and highest ROC-AUC of 0.9161, while SVM had the lowest FAR of 4.88%. We selected and retained Random Forest for production because its decision trees natively provide Mean Decrease in Impurity feature importances, powering real-time keystroke diagnostic tips in the UI without latency-heavy SHAP explainers. Sessions 5–8 were never touched for tuning, and the model uses Option B strict calibration."

Bonus Capabilities

Data Drift Detection & Explainability

Bonus B: Data Drift Check

Script: monitoring/drift_check.py

Performs two-sample Kolmogorov-Smirnov (KS) tests comparing production inference distributions against enrollment training baselines across all 31 features.

Bonus A: Feature Importance

Random Forest feature importance weights exposed via POST /predict API and visualized in the UI. Confirms H.Shift.r, H.t, and H.i drive biometric decisions.

Privacy-by-Design Compliance

In accordance with biometric privacy standards (GDPR), the system logs only timing durations and match scores in monitoring/prediction_logs.jsonl. Keystroke characters, passwords, usernames, and IP addresses are never logged or stored.

Speaker Notes: "Cover our bonus implementations: automated drift detection using two-sample Kolmogorov-Smirnov tests to catch typing rhythm shifts over time, and dynamic feature importance in the UI. Also emphasize that we practice privacy-by-design by logging only timing floats and scores—never passwords or personal information."
